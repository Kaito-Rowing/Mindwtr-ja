# Mindwtr Unreleased

Changes collected since the latest stable release.

- Sync no longer reports a conflict when two devices auto-archive the same task before syncing; both keep the later archive time (#1430).
- Projects have a third Flow mode, **Per section**: each section is Parallel or Sequential, so one section moves step by step while another offers all its tasks at once. Sections never wait for each other, and tasks with no section are Parallel. Set it in a section's menu on desktop or in **Sections** on mobile. Older app versions show such a project as Parallel (#1429).
- Android and iPhone native apps: in Contexts, tapping a context or tag switches to it and a long-press adds it to the selection, as in the main mobile app (#1427).
- Two new themes on desktop and mobile: **Gruvbox Light** (the soft variant) and **Gruvbox Dark**. Status and context colors use the Gruvbox palette, darkened where needed so text stays readable (#1426).
- Contexts view: a nested context or tag such as `@person/todd` that follows its parent `@person` now shows as `/todd`, so a family of contexts reads as one group. The full name stays in tooltips and for screen readers. This applies on desktop, mobile and the native apps (#1428).
- Mobile App Lock: a new **Require unlock** choice (Immediately, After 1 minute, After 5 minutes, After 15 minutes) lets you switch to another app briefly without unlocking again. Immediately stays the default, and opening the app after it was closed always asks. The choice stays on this phone and is kept when you restore a backup (#1423).
- Quick add reads `@person/todd` and `@"Two words"` as one context or tag, even when no task uses it yet. Before, `@person/todd` became `@person` with "/todd" left in the title, and a quoted context swallowed the rest of the line. Android task widgets now pre-fill these names too (#1428).
- Contexts view: tapping a context or tag now switches to it instead of adding it to the selection. To combine several, long-press a chip on mobile, or Ctrl-click (Cmd-click on macOS) on desktop (#1427).
- Android: a task widget that shows one context or tag now opens quick capture with that context or tag already typed in, so the new task gets it. You can edit or delete it before saving (#1418).
- Android: reminders for tasks synced from another device (for example, a task with a due time made on Windows) are now set by the background sync, even when Mindwtr was swiped away. Before, the reminder was set only when the app opened again (#1424).
- Desktop: a link in a task's collapsed description preview now opens when clicked, without expanding or collapsing the task (#1425).
- Android: turning off "Expose to system search" now removes Mindwtr's items from system search even when the app closes or the removal fails right after, or when the switch goes off while the index is being rebuilt. Before, the items could stay searchable with the switch off.
- Mobile: taking Undo after a restore, merge or import now brings attachments back with their files, as long as the app stays open and no newer restore, merge or import came after it. Before, a sync that ran in between could delete the files of attachments the restore had removed, and Undo then showed them as available with nothing on the phone. A restore or snapshot restore also marks any attachment whose file is missing on the phone, so the next sync downloads it again.
- Linux desktop: **Copy Title**, **Copy task link** and **Copy task ID** in the task menu no longer fail now and then with "Could not copy task". The menu could lose the click before the copy ran, and WebKit then refused the clipboard write (#1327).
- Mobile: Contexts has a Sort button beside its search, so you can see and change the list sort there, as in Inbox (#1415).
- Task lists on desktop and mobile can sort by **Priority** (highest first, tasks without a priority last). Priority is offered only while Priorities is on, and not as a project's own sort or in Done and Archive (#1415).
- Reference: a Reference item's list now has checkboxes on desktop and mobile, so you can tick entries off (for example, movies you have watched). A ticked entry is struck through, and **Reset checklist** unticks them all. The item itself stays in Reference: ticking every entry never marks it done or puts it in Focus. Pasted `- [x]` lines keep their tick (#1416).
- Android: Back now leaves multi-select in task lists, projects, Contexts, Review and Trash, instead of leaving the screen or closing the project. The Contexts selection bar uses the same X button and compact buttons as Inbox, so there is no "Done" button next to the Done status (#1415).
- Sync: an attachment another device changed is no longer overwritten by this device's older copy when its download is delayed (a failed download, the per-sync download limit, or a sync that ended early). The older file now waits for the newer version instead of being uploaded as a local edit.
- Sync: settings pages, saved filters, the task editor, Process Inbox and the project sheet no longer put back values another device synced while they were open. Only what you changed is saved, and lists (tags, contexts, checklist items, attachments) merge item by item, so nothing another device added or removed is lost.
- Sync: an edit made while a sync was saving no longer overwrites what another device had just synced. Attachments, checklist items, tags and contexts, Someday section moves and Undo now apply to the task or project as sync left it, so the other device's change stays.
- Mobile: a recovery snapshot taken right after the phone's clock went back is no longer deleted at once. Before, five snapshots named for the later time outranked it, so Undo on that import or restore could not find its snapshot.
- Mobile: restoring a recovery snapshot larger than the backup limit (128 MB) now stops with the backup's "file is too large" message before it is read into memory, as a picked backup file already does.
- Mobile: a failed Restore backup, Merge backup or snapshot restore shows the failure's own words, without the "Error:" prefix.
- Android: a backup cut short while it was written into a picked folder (the app was closed mid-write) is deleted when Settings › Data opens again or the next export starts, so a partial file no longer looks like a finished backup.
- Mobile: restoring a backup or a recovery snapshot no longer turns App Lock off. App Lock belongs to the phone: a restore keeps it on, whatever the backup file says.
- Mobile: an import or backup preview and its result leave a blank line before the project list and before the warnings, as they always meant to; the lines ran together before.
- Mobile: while Settings › Data › Getting Started is adding its tutorial project, the export, restore and import rows wait. Before, a restore started at that moment could replace the library under the new project.
- Imports: a ZIP export whose recorded file sizes do not match its contents is refused as damaged. Before, such a file could import only part of a list, or count one file many times.
- Mobile: a Calendar week with a deadline opens on the selected day (else today). Deadlines widen each day column, so fewer days fit; the week used to open on an earlier day, with the selected day off screen.
- Android security: a file shared into Mindwtr is copied under a generated name, and only another app's content link is accepted. Before, a malicious app could pick the copy's name to overwrite Mindwtr's own files, or share a link to Mindwtr's private files (such as its database) so they became an attachment.
- Android File Sync: when the storage app that holds the sync folder cannot list it or read a file in it, the sync now fails with an error. Before, Android could report the folder as empty, and the sync could then write as if the folder held nothing.
- Android File Sync: choosing a sync folder no longer creates an empty `data.json` in it, and a folder the storage app cannot list is refused instead of getting a second `data (1).json`. The first sync writes the file.
- Android File Sync: a sync file that was read only in part (the storage app ended the read early or reported a different size) now fails the sync instead of being treated as damaged and overwritten with this device's data. A storage error that merely mentions `data.json` is no longer mistaken for a damaged file either.
- File Sync (Android and iOS): when the sync file is missing or damaged but an earlier copy of it is still in the folder (for example after a sync was cut off mid-write), the sync now stops with a conflict instead of rebuilding the file from this device's data. The earlier copy, which may hold changes from other devices, stays in the folder untouched.
- File Sync (mobile): the backup of the previous sync file (`data.json.bak`, `data.json.enc.bak`) is now replaced by a newly created file, never rewritten in place or renamed over another device's backup, and a damaged sync file no longer replaces a good backup.
- Android File Sync: choosing a folder where Mindwtr cannot create files is refused at once. Before, Mindwtr rewrote the folder's existing `data.json` to test it, then accepted a folder it could never sync to.
- Android File Sync: folders from storage apps that identify files by number (rather than by path) now sync. Mindwtr finds `data.json`, its backups and the `attachments` folder by the names the storage app reports; before, it could create duplicates or refuse the folder.
- Android File Sync: attachments now upload to sync folders from rclone (RSAF) and other storage apps that do not advertise write support. The sync file already did; attachment uploads failed every time.
- Cloud: when the self-hosted server refuses a request it did not read in full (too large, or refused before its body was read), it now tells the client to close the connection. Before, a client that reused the connection could have its next request misread and refused with an unrelated error.
- Android: when a Tasks widget switches to a saved filter, context or tag, Mindwtr fills it with that list's tasks the next time the app opens, even if no task changed. Before, when Mindwtr was still running in the background, the widget could keep showing the list's name with no tasks until a task changed.
